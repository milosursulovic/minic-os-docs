Getting Started

Running MiniC OS

The fastest path is QEMU with a pre-built kernel image — one command, no toolchain needed. Building from source, or running outside QEMU entirely (VirtualBox, VMware, real hardware), are both covered below too.

1. The fast path: QEMU

Install QEMU if you don't have it: 

sudo apt install qemu-system-x86      # Debian/Ubuntu/WSL
# or your distro's equivalent package

Grab minic-kernel.elf from Download, then: 

qemu-system-x86_64 -kernel minic-kernel.elf
-kernel is a QEMU-only shortcut — QEMU understands the multiboot1 format the kernel is built as and loads it directly, no bootloader needed. Nothing else (VirtualBox, VMware, real hardware) can do this; see running outside QEMU below for those.

You should see the kernel boot straight to a shell prompt (>, on the second row of the screen). Lowercase letters, digits, space, and enter all work at the keyboard. Try help to see every command, or jump into the Shell Guide for what each one actually does.

Attaching a disk

The disk/filesystem commands (disk, diskwrite, mkfs, mkfile, cat, ls, vfscat, vfswrite, install, spawn, ring3go) need a real IDE drive attached — everything else works identically with or without one: 

qemu-system-x86_64 -kernel minic-kernel.elf \
    -drive file=disk.img,format=raw,if=ide

Any raw disk image works — create an empty one with dd if you don't have one yet: 

dd if=/dev/zero of=disk.img bs=512 count=2048   # 1MB
Without -drive attached, disk commands don't crash — disk/diskwrite's underlying ATA driver polls with a bounded wait (about 1,000,000 spins), so a missing drive fails cleanly after a brief pause and reports disk read failed instead of hanging forever.

Headless (no display)

Redirect the serial port to a file instead of attaching a display — useful for scripting or automated testing: 

qemu-system-x86_64 -kernel minic-kernel.elf -display none \
    -serial file:serial.log -no-reboot

Send keystrokes over QEMU's monitor socket by adding -monitor unix:/tmp/qmon,server,nowait, then echo 'sendkey h' | nc -U /tmp/qmon and similar — see the Architecture page for the full recipe this project's own test suite uses.

2. Building from source

MiniC OS is hand-written in freestanding C (originally built in a hand-rolled language called MiniC through milestone 34, then rewritten by hand into C — see the Roadmap). Building it needs a real GCC toolchain (developed against gcc 15) — no separate compiler checkout, no sibling repo, just gcc/ as/ld/objcopy. The toolchain needs to be Linux's, even if you're doing everything else on Windows — WSL works fine for this. 

sudo apt install build-essential   # gcc/as/ld/objcopy, if not already installed

git clone git@github.com:milosursulovic/minic-os.git
cd minic-os
./build.sh

This produces kernel.elf. build.sh is a thin wrapper over a real Makefile — every .c file compiles to its own object with real incremental rebuilds. Other build.sh subcommands (each also runnable directly as make/make run/make disk/ make iso):

CommandWhat it does
./build.shassembles the boot/interrupt/context-switch stubs, compiles every .c file and the ring3 program, links kernel.elf
./build.sh runalso boots it in QEMU with a curses (in-terminal) display, building/attaching disk.img automatically
./build.sh disk(re)builds disk.img — a small, fixed 1MB test disk image, regenerated from scratch each time
./build.sh isoalso packages a GRUB-bootable minic-os.iso — see below
Every .c file still assembles as a 32-bit ELF container even though its code runs in real 64-bit long mode — QEMU's multiboot1 -kernel loader hard-rejects a genuine ELF64 image. Each file compiles to assembly, gets a .code64 directive prepended, and is fed to as --32, which encodes the 64-bit mnemonics correctly while keeping the ELF32 container. See Architecture for why.

3. Running outside QEMU (VirtualBox, VMware, real hardware)

QEMU's -kernel flag is a convenience shortcut that only QEMU offers. Everywhere else needs a real bootloader in front of the same kernel image — since the kernel is already multiboot1-compliant, GRUB2 can chainload it directly with zero kernel-side changes, just packaging into a bootable ISO.

Building the ISO needs a few extra host packages: 

sudo apt install grub-pc-bin grub-common xorriso mtools
./build.sh iso   # produces minic-os.iso

Or grab a pre-built minic-os.iso from Download.

VirtualBox

  1. New VM — Type "Other", Version "Other/Unknown (64-bit)". No guest additions, no EFI (this kernel boots via legacy BIOS + GRUB).
  2. 128MB of RAM is plenty. A virtual hard disk is optional — the kernel boots fine without one; only the disk/filesystem shell commands need one actually attached.
  3. Settings → Storage → attach minic-os.iso as the optical drive, and (optionally, for disk commands) attach a raw disk.img as a plain IDE hard disk on the same controller.
  4. Start the VM — GRUB's menu appears, then boots straight into the kernel.
VMware and real hardware (write the ISO to a USB stick with dd or a tool like Rufus/balenaEtcher) should work the same way — this hasn't been verified on either yet.
