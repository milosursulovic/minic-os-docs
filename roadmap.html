Roadmap

Every milestone, in order

Each milestone below was scoped as one hard problem, proven with a concrete assertion in QEMU, then shipped — not designed far in advance. The long-term architecture (a UNIX namespace/shell + NT-style kernel objects/handles + microkernel-ish IPC/service isolation + a capability security model, exposed through a native API with a POSIX compatibility layer on top) is planned in phases, each becoming a real numbered milestone when its turn comes. Milestones 1 through 34 were built in MiniC, a hand-rolled language with its own compiler; right after milestone 34 shipped, the kernel was rewritten by hand into freestanding C — see that entry below for the real, dated story.

Milestones 1–10: the foundation

  • 1: boot to 64-bit long mode + VGA text output done — a multiboot1 image boots in QEMU, transitions from 32-bit protected mode into 64-bit long mode, and writes to the VGA text buffer directly from ordinary MiniC. The 32-to-64-bit transition is hand-written in boot/boot.s — below what asm(...) can express, same as every kernel project. Everything past that point is MiniC.
  • 2: real interrupts done — an IDT built as an ordinary MiniC array of packed struct entries, the 8259 PIC remapped, the PIT reconfigured to ~100Hz, working timer + keyboard handlers.
  • 3: heap + a minimal shell done — a bump allocator over the identity map, plus an interactive shell built on the keyboard handler's line buffer.
  • 4: a real free-list heap done — kalloc splits blocks, kfree coalesces adjacent free ones forward.
  • 5: two-way coalescing + a physical frame allocator done — kfree coalesces backward too, and a frame bitmap allocator is built from the multiboot memory map.
  • Language cleanup done — five milestones of real kernel code surfaced six genuine MiniC language gaps (char literals, char arithmetic, a rigid sizeof, no break/continue, array decay stopping short of void*, extern restricted to functions) — all fixed as real compiler features in the minic repo.
  • 6: real dynamic paging done — walks/creates a full PML4→PDPT→PD→PT chain of 4KB pages on demand, so the kernel can map memory anywhere, not just inside the static identity map.
  • 7: a frame-backed, dynamically growing heap done — the heap grows a chunk at a time as the free list runs dry, instead of a fixed reservation.
  • 8: a cooperative scheduler done — a hand-written context switch, a fixed table of tasks each with its own stack, round-robin via voluntary yield().
  • 9: preemptive scheduling done — the timer interrupt now forces a task switch, not just voluntary cooperation.
  • 10: real task blocking via sleep() done — a task can step out of the round-robin for a given number of ticks.

At this point everything still ran in ring 0, sharing one page-table hierarchy — "tasks" were kernel threads, not isolated processes. The long-term architecture plan was settled here, and every milestone since has been a real numbered step toward it.

Phase I–V: ring 3, isolation, the object model, IPC

  • 11: ring 3 + syscalls done — the first real ring0/ring3 privilege boundary: a GDT ring3 code/data pair, a TSS (RSP0 on its own dedicated stack), and an int 0x80 syscall gate (DPL=3) with a minimal dispatcher. Address-space isolation deliberately deferred — proving the privilege-transition mechanism itself came first. Verified by reading back cs=0x1B from inside ring3 (real CPL 3, not just "a syscall happened").
  • 12: per-process address spaces done — real address-space isolation: each task can get its own PML4, with a private region no other task can see even at the identical virtual address. Verified: the same virtual address genuinely resolves to two different physical frames depending on which address space is asking.
  • 13: a real Process concept + a loader done — wires ring3/syscalls and per-process address spaces together: a loader copies a byte range into a freshly cloned private address space and schedules it as a genuinely preemptible ring3 task.
  • 14: kernel object model + per-process handle tables done — the NT-style piece: a kernel-wide object table plus a per-process handle table, bounds-checked and existence-checked, never trusted as a raw index.
  • 15: IPC channels between isolated processes done — real blocking message-passing, reusing the scheduler's existing blocking mechanism (a second wake condition alongside the existing tick check) instead of inventing a second one.

Phase VI–VII: storage, VFS, real process spawning

  • 16: a legacy ATA PIO disk driver done — the first real storage I/O this kernel has ever done, talking directly to the classic ISA IDE ports. Verified three independent ways, including confirming a write directly in the disk image file from the host afterward.
  • 17: MiniFS, a minimal custom filesystem done — a fixed-layout superblock + a one-sector flat directory + a contiguous per-file data region. Verified formatting, creating two files, and reading each back correctly and distinctly.
  • 18: a VFS abstraction over MiniFS done — a basic namespace (/system, /devices) via a small mount table — the identical read call reaches two completely different mechanisms depending only on the path prefix.
  • 19: real Process.spawn() from disk done — "the shell launches a program" becomes genuinely real, reading a file through the VFS instead of a statically embedded blob. Running two ring3-capable processes at once immediately reproduced a real TSS.RSP0 collision, fixed by giving every ring3 task its own private RSP0 target.

Phase VIII: MiniC methods, the native API, a POSIX shim

  • 20: real method-call syntax in MiniC itself done — a compiler-repo milestone, not a kernel one: <ReturnType> <StructName>.<method_name>(<StructName>* self, ...) declarations. Needed zero parser changes at call sites — every bit of new logic lives in codegen. Pure syntax sugar, not a new dispatch mechanism. See minic's examples/methods_demo.mc.
  • 21: a real compiled-MiniC program running in ring3 done — every ring3 program until now was hand-assembled; the loader's "copy one contiguous byte range, jump to its first byte" model doesn't survive unmodified for compiled output, since string literals and globals land in separate ELF sections. Fixed with a standalone link + objcopy -O binary flattening step, no compiler changes.
  • 22: a real native "File" API with real methods done — the first slice of the native System API. Two new syscalls expose VFS read/write to ring3 for the first time; File.write(...)/File.read(...) are real methods wrapping them — the first time this kernel's method-call syntax got used for something real.
  • 23: real Process/Channel methods done — wraps the other two native-API resources the same way. channel_receive is this kernel's first ever blocking syscall. A ring3 process blocks on an operator-triggered channel and then spawns a second instance of itself once triggered.
  • 24: a thin POSIX-shaped shim done — open/read/write/close, implemented entirely in ring3 MiniC over the existing File API, no new syscalls or kernel changes. Growing the compiled ring3 program past one page for the first time surfaced three real, previously-latent kernel bugs — see the Architecture page.

Phase VIII (milestones 20–24) is complete. See the Architecture page for the technical detail behind each of these, and the Walkthrough for real captured proof.

Phase IX: capabilities & security hardening

  • 25: real per-handle rights on Channel done — Phase IX's first step, closing the exact gap milestone 23/24 flagged: a valid channel handle could be used for any operation the channel supported, with no per-handle ownership. A new Handle.rights bitmask (fixed forever at grant time) and a new OBJ_CHANNEL object type wrap Channel in the handle table for the first time. channel_send/channel_receive now resolve a real handle and check its rights before touching the underlying channel; a new open_channel syscall is the one place an index becomes a handle — and always grants receive-only rights, a real and deliberate policy choice, not a placeholder. Verified in QEMU: a fresh boot's Channel.open() succeeds, an immediate unauthorized Channel.send() through that exact handle is correctly rejected, and the authorized Channel.receive() on the same handle still works normally afterward. See the Architecture page and the Walkthrough for the real rejected-send proof.
  • 26: security hardening on the shared PDPT region done — Phase IX's second step, closing the shared-region gap flagged since milestone 12. Tracing every actual leaf-level map_page/map_page_in call site first showed the real, exploitable surface was narrower than assumed — the heap and the map demo already used leaf flags without the user bit, so the true gap was specifically boot.s's static identity map's 2MB huge-page leaves (PDPT index 0). clone_address_space() now strips the user bit from its copy of the kernel's PDPT[0]/PDPT[1] entries when building a new (ring3-capable) address space — the original kernel address space and boot.s itself are untouched, since nothing runs those in ring3 anyway, and every legitimate ring3 interaction with this region already goes through a syscall regardless. Verified with a genuine negative-space proof: a new shell command, ring3fault, sends a deliberate forbidden-write trigger, and the boot-time ring3 process's attempted write to the kernel's own load address (0x100000) takes a real page fault — the existing handler reports the exact faulting address and halts, and the "it worked" line the test was written to catch never prints. A full regression pass confirmed nothing legitimate broke. See the Architecture page and the Walkthrough for the real captured fault.
  • 27: real per-handle rights on Process done — Phase IX's third step. The real gap was narrower than "Process has no rights": RIGHT_QUERY already existed and was already granted to every process's own self-handle since milestone 14, but syscall 3 (query) never checked it — any valid OBJ_PROCESS handle could query regardless of rights. Fixed by inlining the same rights-check style syscalls 7/8/9 use (the now-unused resolve_handle() removed). New syscall 10 (open_process) is the first real cross-process capability — given another task's index, it mints a handle to that process with the intersection of a caller-requested rights bitmask and what's grantable (RIGHT_QUERY only, today). Verified in QEMU: after spawning a child, the parent opens a handle to it with rights=0 and its .query() is correctly rejected, then opens a second handle with RIGHT_QUERY that succeeds and reports the exact task_index Process.spawn() already returned — an independent cross-check, not a hardcoded echo. The pre-existing self-handle query (rights-granted since milestone 14, verified for the first time here) still works, confirming the newly-real check doesn't break the one path already using it. A full regression pass (heap, paging, scheduler, milestone 26's ring3fault hardening, milestone 25's Channel rights) stayed clean.
  • 28: NX enforcement on dynamically-mapped data regions done — Phase IX's fourth step, scoping "security hardening (NX/ASLR/sandboxing)" down from three genuinely different mechanisms to the first: NX/DEP, the classic W^X protection against injected shellcode. boot.s sets EFER.NXE in the same MSR round trip as the existing EFER.LME — order matters, since a PTE's NX bit (bit 63) is a reserved-bit violation before NXE is live. mm/paging.mc gained PAGE_NX, threaded through map_page_in()'s leaf flags — the CPU ORs the NX bit across translation levels (opposite of the "user" bit's AND semantics milestone 26 worked around), so only the leaf entry needed touching. Applied to every dynamically-mapped pure-data region: the heap, the map demo, the scheduler's private demo mapping, and every ring3 process's own user stack — deliberately not applied to a loaded ring3 program's own image, since the loader still has no tracked code/data boundary within it (a separate, open problem). New shell command ring3nx writes a real ret opcode onto the boot-time process's own stack and attempts to execute it; the resulting page fault's error code (0x15) has the CPU's own instruction-fetch bit set, independently distinguishable from ring3fault's write-violation code (0x7) — isr/isr.mc now prints that error code for every page fault, not just GPFs. A real bug was found and fixed during this milestone's own regression pass: translate_in()'s physical-address extraction didn't mask out the new NX bit, corrupting reported addresses for any NX-marked page — caught by procs' own existing check. A full regression pass after the fix confirmed everything else stayed clean. See the Architecture page and the Walkthrough for the real captured fault.
  • Phase IX is now considered substantially complete. ASLR and true process sandboxing remain open, unscoped ideas for a future revisit — ideas, not commitments — but the concrete gaps this phase set out to close (capability rights on both Channel and Process, and real memory-protection hardening on the shared region including NX) are all done.

Phase X: driver framework (PCI) + networking

  • 29: PCI bus enumeration done — Phase X's first step, and the necessary prerequisite for everything else in this phase: a NIC driver can't be written against a hardcoded, assumed I/O port the way disk/ata.mc's 0x1F0 was — it has to be discovered. New drivers/pci.mc walks the legacy CONFIG_ADDRESS/CONFIG_DATA mechanism (ports 0xCF8/0xCFC, drivers/io.mc's new 32-bit outl/inl) across bus 0's 32 device slots, probing functions 1–7 only for devices whose header-type byte marks them multi-function. Deliberately scoped to bus 0 only — no PCI-to-PCI bridge recursion, since QEMU's default machine has none. Verified against something this kernel had no part in choosing: every device found (0x8086:0x1237 host bridge, 0x8086:0x7000/0x7010/0x7113 ISA/IDE/ACPI bridges, 0x1234:0x1111 Bochs VGA, 0x8086:0x100e an Intel e1000 NIC) is a real, publicly-documented vendor:device ID pair matching QEMU's own default machine model exactly — and 0x7010 is literally the same IDE controller disk/ata.mc already talks to, now independently discovered rather than assumed. Finding a real e1000 NIC with zero extra QEMU flags is a useful bonus: the next Phase X milestone has a real target device already in hand. A regression pass (disk/diskwrite interleaved with pci, confirming the new 32-bit port-I/O globals don't corrupt the ATA driver's own shared staging globals; heap; scheduler) stayed clean. See the Architecture page and the Walkthrough for the real captured output.
  • 30: a real e1000 NIC driver (initialization only) done — Phase X's second step, deliberately scoped to enabling the device and reading back real hardware state, not sending or receiving a packet yet (RX/TX descriptor rings are a separably-sized hard problem of their own). New net/e1000.mc enables the device over PCI (drivers/pci.mc's new pci_config_write_dword() — this kernel's first PCI config space write), reads BAR0 to find its real physical MMIO base, and maps it into the kernel's own address space via mm/paging.mc's ordinary map_page() — the first time this kernel has mapped device registers rather than RAM. A real assumption confirmed rather than hoped: BAR0 already holds a valid, SeaBIOS-assigned address, since QEMU's -kernel boot still runs SeaBIOS's own PCI enumeration before the kernel gets control. Reads the MAC straight from RAL0/RAH0 (pre-loaded by QEMU's emulated EEPROM) rather than implementing the EEPROM-read protocol separately. Verified against something this kernel had no part in choosing: the real MAC read back, 52:54:00:12:34:56, is QEMU's own well-known default NIC MAC, and the link-up bit reports real hardware state too. A regression pass (pci re-run after the new config-space write; disk/diskwrite/mkfs; heap; paging; scheduler) stayed clean. See the Architecture page and the Walkthrough for the real captured output.
  • 31: real TX/RX descriptor rings and a genuine packet round trip done — Phase X's third step, built directly on milestone 30's own groundwork (MMIO already mapped, PCI bus-mastering already enabled). New packed struct TxDescriptor/RxDescriptor match the hardware's own 16-byte layout exactly; e1000_init_rings() allocates and programs both rings (using alloc_frame()'s own frames directly as physical DMA buffer addresses); e1000_send() polls the hardware's own descriptor-done status bit for real confirmation, the same bounded-poll discipline disk/ata.mc already established. Deliberately not a real ARP subsystem — the new arp command crafts exactly one hardcoded Ethernet+ARP request as a real external test stimulus, not a general address-resolution mechanism, the same "one hardcoded test case" scope milestone 26's ring3fault used. A real fix found during testing: the first RX poll attempt used a raw instruction-count spin bound and got nothing back — not a driver bug, a measurement one, fixed by polling against isr/isr.mc's own g_tick_count instead, since a tight spin loop doesn't reliably correspond to real wall-clock time. Verified with the strongest proof this driver has produced yet: TX confirmed by hardware, and RX confirmed by a genuine reply from QEMU's real network stack — from=52:55:0a:00:02:02/sender_ip=10.0.2.2 are QEMU's own documented default gateway MAC/IP, not anything fabricated. A full regression pass (heap, paging, scheduler, nic, pci, disk/diskwrite) stayed clean. See the Architecture page and the Walkthrough for the real captured output.
  • 32: a real ARP resolver done — Phase X's fourth step, replacing milestone 31's own hardcoded one-shot request/reply with a genuine resolver built on the proven TX/RX plumbing. New net/arp.mc: a fixed-size cache (ArpEntry[8]), arp_resolve(ip, mac_out) checks the cache first and only sends a real request on a miss, polling for a genuinely matching reply against a real g_tick_count-bounded timeout. Deliberately scoped as a client (resolver) only, not a responder — this kernel has no assigned IP address of its own yet. The shell's arp command (same name, now backed by the real mechanism) runs four checks: resolve the gateway (a real external round trip, non-trivial elapsed ticks), resolve it again (zero elapsed ticks — a real, timing-based proof of the cache), resolve a second, different real address (QEMU SLIRP's own DNS proxy, 10.0.2.3 — proving genuine generalization, not one fixed IP), and resolve an address nothing answers for (correctly returns false after the real timeout, not a hang). A full regression pass (heap, paging, scheduler, pci, nic, disk/diskwrite) stayed clean. See the Architecture page and the Walkthrough for the real captured output.
  • 33: a real IPv4 layer, verified with a genuine ICMP echo (ping) round trip done — Phase X's fifth step, and the first milestone to give this kernel a real, explicit concept of "my IP address" (net/ip.mc's g_my_ip, previously a bare literal duplicated inside net/arp.mc's own request-building code, now one shared, named value both files use). New net/ip.mc: ip_checksum() (the real RFC 791 one's-complement checksum, also reused for ICMP) and ip_build_header() (a real 20-byte, no-options IPv4 header). New net/icmp.mc: icmp_ping() — the minimal, natural verification vehicle for "does IP genuinely work end to end," the same relationship milestone 31's hardcoded ARP request had to proving TX/RX worked at all. Resolves the target's MAC via milestone 32's real arp_resolve() first, builds a real Ethernet+IPv4+ICMP echo request, sends it, and polls (real g_tick_count-bounded) for a reply matching on every real field: EtherType, IP protocol, source IP, ICMP type, and the exact identifier/sequence number sent. Verified in QEMU: ping gateway ok=0x1 elapsed_ticks=0x64 — a genuine reply from QEMU's real network stack, the same non-trivial round-trip time arp already measured, no bugs found (the hard, novel risk was already absorbed by milestones 31/32; this one cleanly applied already-proven mechanisms to a new protocol layer). A full regression pass (heap, paging, scheduler, pci, arp's own continued correctness after the g_my_ip refactor) stayed clean. See the Architecture page and the Walkthrough for the real captured output.
  • 34: a real UDP layer, verified with a genuine DNS query done — Phase X's sixth step. UDP is the simpler of the two remaining transport protocols — no connection state, no retransmission/congestion control, just a port-addressed datagram wrapper over the now-working IP layer. New net/udp.mc: udp_checksum() (the real pseudo-header algorithm, reusing ip.mc's ip_checksum() unchanged) and udp_send()/udp_receive() (the same resolve-then-send-then-poll shape milestone 33's ICMP code already established). New net/dns.mc: dns_query() — a minimal, hand-crafted DNS query, deliberately not a real DNS client, purely as a real external verification vehicle for UDP, the same "one hardcoded real-protocol message" discipline ARP's request and ICMP's ping both already used. Sent to QEMU SLIRP's own built-in DNS proxy (10.0.2.3) and verified on the exact transaction ID, the response bit, and a real answer count. Verified in QEMU: dns query ok=0x1 elapsed_ticks=0x74 — noticeably higher than ping's own elapsed_ticks=0x64, a real, sensible detail (DNS genuinely takes one more hop than ICMP echo). No bugs in the protocol logic itself — only two ordinary MiniC type-mismatch compile errors, fixed by restructuring. A full regression pass (heap, paging, scheduler, pci, ping's own continued correctness) stayed clean. See the Architecture page and the Walkthrough for the real captured output.
  • The MiniC → C rewrite done — right as TCP was about to get its own dedicated scoping pass, the decision was made to retire MiniC (and its own compiler/docs repos) entirely and rewrite this whole kernel by hand into freestanding C, for faster day-to-day development going forward. Every one of the ~34 source files (and the shell, kept around one stage longer than the rest purely as a porting reference) was rewritten and independently re-verified in QEMU against its own already-known-good milestone output before being deleted — not a bulk mechanical translation trusted on faith. One real, C-specific bug was found and fixed: spawn_process()'s "jump to byte 0 of the loaded image" loader assumed the entry function always lands first — true for MiniC's own single-pass codegen, but not for gcc, which laid out the ring3 program's functions in a different order — fixed with a dedicated linker section pinning _start to offset 0 regardless of source order. Everything else carried over unchanged in behavior: same architecture, same milestones, same verification bar, same "no external libraries" rule — only the implementation language changed. See the kernel repo's own README for the full writeup and one commit per rewrite stage.
  • 35: a real TCP client, verified with a genuine HTTP GET to a real internet host done — Phase X's seventh and final step, the first genuinely stateful transport protocol in this kernel and the first time any protocol layer here has talked to something off the local SLIRP subnet. New net/tcp.c: tcp_checksum() (the same pseudo-header shape UDP's own checksum already established, protocol number 6 instead of 17) and tcp_fetch() — a client-only, single-connection round trip: a real 3-way handshake (SYN, wait for a genuinely matching SYN-ACK, ACK), a real data segment carrying an actual HTTP/1.1 GET request, a receive loop that ACKs each arriving segment until the peer's FIN or the buffer fills, and a best-effort graceful close. The real new distinction this milestone had to get right that no earlier layer here ever needed: every previous ARP/ICMP/UDP target sat on the local subnet, so ARPing it directly always worked — a real internet host doesn't answer ARP from this guest at all, so tcp_fetch() ARP-resolves the gateway's MAC for the Ethernet-level destination while putting the real remote IP in the IP header, the same next-hop-vs-final-destination distinction every real router relies on. Extended net/dns.c with a real dns_resolve_a() that actually parses the answer section (handling DNS-compression pointers and skipping past CNAMEs) instead of just checking the header, so the demo's target is a freshly-resolved real IP, not a hardcoded one that could go stale. Verified in QEMU, twice, independently, against two different real IPs for example.com (Cloudflare's own round-robin DNS, both confirmed via a real curl from the same environment): a complete handshake, a full 512-byte real HTTP response, and a confirmed real HTTP status line at the start of it — not "some bytes arrived," a specific, checkable claim about what those bytes actually are. No retransmission, congestion control, listening/server side, or connection table — real, substantial follow-on work, not oversights. See the Architecture page and the Walkthrough for the real captured output.

Phase XI — service architecture + a real init

  • 36: a real init process done — Phase XI's first step, deliberately narrow. A new, dedicated ring3 process, proc/init.c, spawns a real service (proc/hello_service.c) via a new syscall 11 (spawn_builtin) referencing a small, fixed, kernel-embedded program registry addressed by index — not a raw pointer, which would let ring3 code claim any address in memory is a valid program image, exactly the hole the capability/rights phase (milestones 25-27) worked to close everywhere else. This also sidesteps a real chicken-and-egg problem: a fresh disk.img has no files on it until mkfs+install run manually, so a real init can't depend on the filesystem existing yet — spawn_process_from_path() (syscall 6) already covers "spawn a real file from disk" for when that's what's wanted. Deliberately does not touch the existing boot-time demo process (proc/ring3prog.c, unchanged) or the kernel's own debug shell (shell/shell.c's ~40 commands stay kernel-mode — most of them touch raw kernel internals like physical frames directly, which shouldn't be a userspace syscall in a real design anyway). A real bug was hit and fixed while wiring the registry: a static array of pointers initialized with &symbol expressions needs an absolute 64-bit relocation not representable in the kernel's ELF32 build container — fixed by resolving the address at the point of use instead, an ordinary RIP-relative reference. Verified in QEMU, twice: init's own startup and spawn-confirmation messages, hello_service's own message, and ps independently confirming three distinct processes with three distinct cr3 values — init's self-reported task_index matches ps's own output exactly, not an unverified echo.
  • 37: real process exit done — Phase XI's second step, closing a gap flagged since the earliest process-model milestones. New syscall 12 (process_exit) marks the calling task's slot and process slot as no-longer-alive, then yields away for the last time; the scheduler's scan (sched/task.c's yield()) permanently skips a slot marked this way — the exact same shape it already uses to skip a temporarily blocked task, just with no wake condition that will ever fire. task.used/process.used turned out to already exist but be entirely write-only (set true at creation, never read anywhere) — repurposing them as real "is this still alive" flags needed no new fields, just giving existing ones their first real meaning. Deliberately does not reclaim resources on exit — frames stay mapped, the table slot stays occupied forever, and any handle still pointing at an exited process stays valid but now points at something that will never run again; real, separate follow-on work. proc/hello_service.c now calls process_exit() right after its own startup message instead of idling forever — the cleanest possible checkable claim for "a process can genuinely stop running." shell.c's ps gained an exited=0x field per process. Verified in QEMU, twice: ps shows hello_service's exited=0x1 while the boot-time demo and init both stay exited=0x0; tasks confirmed the scheduler and every pre-existing demo task stayed healthy, and install+spawn still worked correctly alongside the now-exited process, spawning a fourth process cleanly.
  • 38: process supervision done — Phase XI's third step, closing the loop milestones 36 (spawn) and 37 (exit) opened separately. init.c now opens a ProcessHandle to its spawned service, busy-polls its query until the service has genuinely exited, and spawns a fresh instance — a real restart, not just spawn-and-forget. The real bug this needed: syscall 3 (handle query) resolved an OBJ_PROCESS handle straight to a task_index without ever checking whether the target had exited, so querying a handle to an already-dead process silently returned a stale task_index instead of failing — fixed with a one-line check against g_processes[proc_idx].used. Deliberately restarts only once, not in a loop: the process table is a fixed 4 slots (the boot-time demo + init + two hello_service instances already fills it), and resource reclamation on exit still doesn't exist (milestone 37's own deferred item) — a real supervisor loop needs that first. Verified in QEMU, twice: init's own "exited, restarting" and "restarted ... task_index=0xb" messages, hello_service's second startup message, and ps independently showing 4 distinct processes with both service instances exited=0x1. Confirmed the honest consequence of the now-full table: ring3go's own Process.spawn() correctly fails once init's two spawns have used the remaining slots.
  • 39: free a process's frames on exit done — Phase XI's fourth step, closing the resource side of milestone 37's own deferred item. New mm/paging.c function free_address_space(pml4_phys) walks the exiting process's own page tables — PDPT[2..511] -> PD -> PT (the private per-process region; PDPT[0]/[1], the shared kernel/heap sub-tables, are never touched) — freeing every present leaf frame plus the PT/PD frames themselves, then the process's own PDPT and PML4 frames. Safe to call from inside process_exit() even though it tears down the caller's own address space: the syscall runs in kernel mode on the shared identity map the whole time, and CR3 only actually moves off the freed PML4 once yield()'s own load_cr3() runs immediately after. Still not reclaimed: the process/task table slot itself (a separate step - real bookkeeping this milestone didn't add), and the task's own kalloc'd kernel stack (freeing your own currently-executing stack from within itself is a genuinely riskier problem). Verified in QEMU with real diagnostic prints of g_free_frame_count around the free (added, used, then removed): both of hello_service's exit cycles return the free count to the identical baseline, not drifting, and ps showed the second spawn's cr3 is bit-for-bit the same physical frame the first spawn's exit had just freed - real reuse, not coincidence.
  • 40: process/task table slot reuse done — Phase XI's fifth step, closing the last piece milestone 37/39 deferred: spawn_process()/create_task_with_cr3() now search for an exited slot before appending, so the table no longer only ever grows. create_task_with_cr3() changed from bool to int (the real task index, or -1) - needed since a reused slot's index can't be inferred as "whatever the counter currently is" anymore. That change surfaced two real, previously-latent bugs, both fixed: process.c's own pre-computed task_index = g_task_count would have used the wrong index once reuse landed, and create_isolated_task()'s bare return create_task_with_cr3(...) implicitly converted -1 (failure) to true via nonzero-is-truthy — silently reporting success on failure. A genuinely elegant piece: a reused task slot reuses its old kalloc'd kernel stack directly (just reinitializes the fake switch-frame at the top of the same block) instead of allocating a fresh one - sidesteps "freeing your own currently-executing stack from within itself" entirely rather than solving it, and means slot reuse doesn't leak heap memory either. spawn_process() also clears the reused slot's handle table first, since a stale "handle 0" from the previous occupant would otherwise break the "handle 0 = myself" convention for the new one. A real regression was found and fixed during this milestone's own testing (never shipped): an early version had init restart hello_service 2-3 times in a loop for a more dramatic proof, but each restart also costs a g_objects[8] slot — looping that aggressively exhausted the shared, still-unreclaimed object table and broke the original boot-time demo process's own unrelated Channel.open() call. Reverted to a single restart, which already proves reuse cleanly without touching that budget any harder than milestone 38 already did. Verified in QEMU: the same task_index/cr3 come back for the restart every time, and ps never grows past 3 processes across repeated cycles (confirmed clean and reproducible across 4 separate runs, after one transient, non-reproducing "0x20" process-count reading was correctly attributed to QEMU/test-harness flakiness rather than a real bug - the same class already documented for the map command's own transient fault earlier in this project's history).
  • 41: kernel object/handle reclamation on process exit done — Phase XI's sixth step, the direct fix for the exact regression milestone 40's own testing found and only worked around: process_exit (syscall 12) never freed anything from the exiting process's own handle table, so g_objects[8] only ever grew even as process/task slots started reusing themselves. New free_object()/free_handle() in proc/object.c — alloc_object()/alloc_handle() already searched for a free slot before appending, they just never had anything freed to find until now. process_exit walks the exiting process's own g_handle_tables[caller_process][...] and frees every object it referenced; spawn_process()'s milestone-40 handle-table-clearing-on-reuse loop is now redundant and removed, since exit itself leaves the table clean for the next occupant. Deliberately scoped narrow: a handle another process holds to the exiting one (e.g. init's own permanent open_process handle onto hello_service) lives in that other process's table, not the exiting process's own, so it isn't touched — and there's still no handle_close-style syscall, so a process that opens handles to others but never exits itself has no way to release them early. Verified in QEMU: objects: 0x4 after a clean spawn/exit/restart/exit cycle, matching hand arithmetic exactly (3 boot-time objects plus 1 permanent init-owned object), and re-running the exact scenario that broke during milestone 40's testing — install+spawn alongside the hello_service restart — now shows Channel.open() ok=0x1 restored, confirming the regression is genuinely fixed rather than just avoided.
  • 42: handle_close — release a handle before exiting done — Phase XI's seventh step, closing the exact gap milestone 41 documented as still open: a handle one process holds to another lives in the holder's own table, so the target's own exit (milestone 41's reclaim) never touches it — only the holder explicitly releasing it, or the holder itself exiting, ever can. New syscall 13 validates the handle belongs to the caller and is in use, then calls the existing free_object()/free_handle() pair (already added in milestone 41) on it — no new reclaim mechanism, just exposing the free path outside process_exit's own walk. init.c now closes its query handle to hello_service after each restart cycle and loops the restart 3 times instead of once — deliberately the exact aggressive-restart scenario that exhausted g_objects[8] during milestone 40's own testing, before any reclaim existed at all. Verified in QEMU, twice: objs reports 0x3 after all 3 restart rounds complete — bit-for-bit the clean-boot baseline, proving 3 full rounds of open/query/close/restart leave zero net object growth, not just a smaller leak than before. ps/frames stayed correct both runs and the unrelated demo process's own Channel.open() stayed ok=0x1, confirming the longer-running init loop introduced no regression.
  • 43: runtime service registration done — Phase XI's eighth step, closing the other item flagged as open after milestone 42: spawn_builtin's registry has been fixed at compile time since milestone 36, so a ring3 process could never make a new program spawnable without a kernel rebuild. New syscall 14, register_service, reads a VFS file into one of 4 fixed 16KB runtime registry slots and returns an index; syscall.c's existing builtin_program_bounds() (already the one thing spawn_builtin consults, by index, never a raw pointer) now checks those runtime slots after the one fixed compile-time entry — index 0 stays reserved for hello_service, indices 1+ map to registered slots. spawn_builtin itself needed no changes at all: extending what builtin_program_bounds() recognizes was the entire feature. proc/ring3prog.c gained a fourth channel-trigger branch: registers its own just-installed /system/testprog.bin at runtime, then spawn_builtins it — deliberately exercising the new index-based path rather than the already-proven VFS-path route (syscall 6). New shell command ring3reg sends that trigger. Verified in QEMU, twice: register_service() returns index 0x1 (the first dynamic slot) both times, and spawn_builtin(0x1) launches a real new process whose own self-query independently reports the exact same task_index — not an unverified echo — running its full File/POSIX/Channel self-test sequence exactly like any other loaded instance. objs read 0x5 after the flow completed, matching hand arithmetic exactly: the 3 boot-time baseline objects plus 2 permanent ones (self + channel_open) from the newly-spawned instance, which — like the original boot-time demo — blocks forever on its own Channel.receive() and never exits. Deliberately narrow: no unregister_service, so the 4 registry slots are a lifetime cap per boot, not a reclaimable resource like every other table this kernel now reuses.
  • 44: unregister_service — free a runtime registry slot done — Phase XI's ninth step, closing milestone 43's own deliberately-deferred gap: the 4 runtime registry slots had no way back to free, unlike every other table this kernel now reclaims (process/task slots since milestone 40, kernel objects/handles since 41/42). New syscall 15 validates the index maps to a currently-used runtime slot, then clears its used flag and length — the same shape as milestone 41's free_object()/free_handle(), just for this table. Deliberately doesn't track which process registered a slot, so any process can unregister any slot — matches the kernel's existing pointer-ownership gap rather than closing it, real separate work. Unregistering doesn't affect a process already spawned from that slot: spawn_process() copies the image into the new process's own address space at spawn time, so nothing keeps referencing the registry slot afterward. proc/ring3prog.c gained a fifth channel-trigger branch, the concrete proof this milestone needed: register, unregister, confirm spawn_builtin on that index now genuinely fails (not just "probably freed"), register again, confirm the same index comes back — real reuse, not a second slot — then spawn_builtin the reused index and confirm it launches a real, working process. New shell command ring3unreg. Verified in QEMU, twice: register_service() → 0x1, unregister_service → 0x0 (success), spawn_builtin(0x1) right after → -1 (correctly fails), register_service() again → 0x1 (same slot reused), and spawn_builtin(0x1) this time launches a real process whose own self-query independently reports the same task_index. objs still read 0x5, identical to milestone 43's own baseline, confirming the register/unregister/re-register cycle doesn't touch the unrelated kernel object table.

Still ahead in this phase: the existing hardcoded shell loop migrating to a real userspace program is explicitly not the next step — most of its command surface touches raw kernel internals that shouldn't be arbitrary userspace syscalls in a real design, a substantially bigger and separate problem from "does a real init exist." Async I/O as a cross-cutting pass once sync I/O works everywhere is the one item still open — with milestone 44, every fixed-size table in this kernel that can fill up during a boot now also has a way to free a slot back for reuse.

Self-hosting used to be framed as "minicc compiled for MiniC OS's own target, running on MiniC OS to compile something" — that goal doesn't carry over as-is now that MiniC itself is retired (see the MiniC → C rewrite above); getting a real C toolchain running natively on this kernel is a substantially bigger undertaking than porting one small hand-rolled compiler was, and isn't a near-term goal. The real prerequisites this kernel already has either way (native API, real file I/O, real process spawning) mean the door isn't closed — just not something to plan around until much later.
