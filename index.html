A kernel, hand-written from scratch

MiniC OS

A multiboot1 x86-64 kernel, every subsystem hand-written from scratch — no external libraries. Originally built in MiniC, a small hand-rolled systems language with its own compiler, no LLVM; then rewritten by hand into freestanding C for faster day-to-day development, one subsystem at a time, each independently re-verified in QEMU before the MiniC original was deleted — same architecture, same verification bar, only the implementation language changed. The only hand-written assembly today is what's genuinely below what a C function body can express: the 32-to-64-bit boot transition, interrupt entry stubs, and context switching.

Every one of those commands is backed by a real subsystem, not a stub: a free-list heap over a physical frame allocator, real dynamic PML4/PDPT/PD/PT paging, a preemptive scheduler, a custom on-disk filesystem, and a real process loader — all hand-written from scratch, all verified in QEMU with a concrete, checkable assertion for every claim (an exact byte count, a register readback, a physical address that genuinely differs between two isolated processes), never just "it didn't crash."

Where this fits

MiniC OS started as the kernel-phase destination of a hand-rolled systems language project called MiniC — the point where the language stopped being exercised by small demo programs and started being exercised by a real kernel with real constraints (no libc, no register allocator, no forward declarations). Every real language gap MiniC OS surfaced (char literals, char arithmetic, break/continue, 2D arrays, const, and eventually real obj.method() syntax) got fixed as a real compiler feature, not worked around and forgotten. Once day-to-day development speed became the priority, MiniC and its compiler were retired and the kernel was rewritten by hand into freestanding C.

What's already real

Ring 0 → ring 3, for real

A GDT ring3 code/data pair, a TSS with a per-task RSP0, and an int 0x80 syscall gate — verified by reading back cs=0x1B from inside ring3, not just "a syscall succeeded."

Real process isolation

Each process gets its own PML4, cloned on spawn — two processes mapping the identical virtual address resolve to two genuinely different physical frames, confirmed with a page-table walk, not just "two different numbers came back." A cloned address space's copy of the shared kernel region is stripped of ring3 access too — a deliberate forbidden write from ring3 takes a real page fault, not a silent success. Real NX (no-execute) enforcement, too — a ring3 process that writes an instruction onto its own stack and jumps to it takes a page fault with the CPU's own instruction-fetch bit set, not a silent execution.

An NT-style object/handle model

Ring 3 code only ever sees a small integer handle, bounds- and existence-checked on every use — never a raw kernel pointer. Real per-handle rights, too: a handle granted with receive-only access genuinely cannot be used to send, checked at the syscall boundary before the underlying object is ever touched. Extends across processes too — one process can open a handle to another with a requested rights set, and gets back only the intersection of what it asked for and what's actually grantable.

Real IPC

Blocking channel receive reuses the exact same scheduler blocking primitive sleep() already proved, generalized to a second wake condition — no second mechanism invented.

A real filesystem, from scratch

A legacy ATA PIO driver, a custom filesystem ("MiniFS") with a real superblock/directory/data layout, and a VFS routing /system and /devices paths to different backends through the identical function call.

Real PCI discovery, a NIC driver, ARP, IP, and UDP

Walks the legacy CONFIG_ADDRESS/CONFIG_DATA mechanism to enumerate real hardware instead of trusting a hardcoded I/O port — every device found checks out against QEMU's own default machine model, vendor:device ID and all. A real e1000 driver enables the NIC it finds over PCI, maps its memory-mapped register file, and moves real packets through real TX/RX descriptor rings. A real ARP resolver sits on top — a genuine cache (a second resolve of the same address returns instantly, checkable by real elapsed ticks) that works for any target address. A real IPv4 layer sits above that, verified with a genuine ICMP echo (ping) round trip, and a real UDP layer above that, verified with a genuine DNS query answered by a real upstream resolver through QEMU's own network backend — not a loopback, not self-validation.

Compiled C running in ring 3

Ring 3 processes are real, gcc-compiled programs — not hand-assembled blobs — using this kernel's own C-shaped native API (file_write(&self, ...), channel_send(...), process_spawn(...) — a plain function taking an explicit self pointer, C's own shape for what used to be self.method(...) sugar), plus a thin POSIX-shaped open/read/write/ close shim layered on top.

Try it

qemu-system-x86_64 -kernel minic-kernel.elf
