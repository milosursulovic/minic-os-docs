Shell Guide

The interactive shell

MiniC OS boots straight into a minimal shell over the VGA text buffer — no windowing, no scrolling (the screen wraps once full), just a prompt (>) and a line buffer built directly on the keyboard driver. Every command below is real, backed by a genuine subsystem, not a stub — see the Walkthrough for a full annotated session proving each one.

Only lowercase letters, digits, space, /, ., and enter are typeable at the keyboard — there's no shift/caps handling and no backspace/editing yet, so a mistyped line has to be submitted and re-typed. echo/vfscat are the only commands that take a free-form argument.

General

CommandWhat it does
helplists every command
clearclears the screen (except the boot message on row 0)
echo <text>prints back whatever follows, verbatim

Timers & interrupts

CommandWhat it does
ticksprints the current PIT tick counter (g_tick_count), incremented by the timer interrupt at ~100Hz nominal (QEMU/TCG's actual effective rate varies a lot, often several times faster)

Heap

A free-list allocator (kalloc/kfree) with two-way coalescing, growing on demand by mapping fresh physical frames rather than a fixed arena.

CommandWhat it does
allocallocates a fixed 64 bytes, prints the returned address
bigallocallocates enough to force the heap to grow past its current mapped region in one call
freefrees the last allocation (tracked automatically)
free <addr>frees a specific hex address (bounds-checked — an address outside the heap arena is silently ignored, not a crash)
memprints free/total heap bytes
resetcollapses the free list back to one block over whatever's already mapped (doesn't unmap/re-grow — that would leak a physical frame per byte remapped)

Physical frames

A bitmap allocator (alloc_frame/free_frame) built by parsing the real multiboot memory map at boot.

CommandWhat it does
frameallocates one physical frame, prints its address
unframefrees the last allocated frame
framesprints free/total frame counts

Paging

CommandWhat it does
mapmaps a freshly allocated frame at a fixed demo virtual address a full 1GB past the boot-time static identity map, writes a known constant through it, and reads it back — proves the whole PML4→PDPT→PD→PT walk, not just that an address came back

Scheduler

A preemptive scheduler — the timer interrupt forces a task switch, not just voluntary yield() — with real blocking (sleep() takes a task out of the round-robin for a given tick count).

CommandWhat it does
tasksprints the boot-time demo tasks' counters: two purely cooperative tasks (lockstep), one that never yields at all (runs orders of magnitude further, proving preemption forces it off the CPU periodically), and one that sleeps between increments (its count tracks ticks / sleep_interval)

Process isolation demo

CommandWhat it does
procstwo boot-time demo tasks (proc_a/proc_b), each with its own private address space, both mapping the identical virtual address to their own physical frame — prints each one's value and physical address, proving real isolation (not just separate stacks)

Process model & kernel objects

An NT-style object model: a kernel-wide object table plus a per-process handle table. Ring 3 code only ever sees a small integer handle — bounds-checked and existence-checked on every use, never trusted as a raw index.

CommandWhat it does
pslists every real process (task index, private address-space base cr3)
objslists every kernel object (type, backing data index)

IPC (channels)

A channel is a single-slot mailbox. send is non-blocking (fails if the mailbox is already full); a blocking receive() reuses the exact scheduler primitive sleep() already uses, generalized to a second wake condition.

CommandWhat it does
chanshows whether the boot-time demo receiver process has gotten a message yet, and what value
sendsends a fixed demo value on that same channel — the blocked receiver wakes up on its own, from a separate isolated address space
ring3gosends a trigger on a second, dedicated channel — this one wakes the boot-time ring3 process's own blocking Channel.receive() syscall, which then goes on to call Process.spawn() and launch a second copy of itself (run install first so the file it spawns actually exists on disk). As of milestone 27, the parent also opens two handles to the child it just spawned — one with no rights (query correctly rejected), one with RIGHT_QUERY (query succeeds) — see Capabilities & rights
ring3faultsends a different trigger value on that same channel — instead of spawning, the boot-time ring3 process deliberately attempts a forbidden write into the kernel's shared region and takes a real page fault (see Memory protection). Halts the kernel — run it in its own dedicated session, never alongside other commands
ring3nxsends a third trigger value — the boot-time ring3 process writes a real instruction byte onto its own user stack and attempts to execute it, proving NX enforcement (see Memory protection). Halts the kernel — same one-shot caveat as ring3fault

Hardware discovery (PCI) & networking

Phase X's own subsystems — the first time this kernel discovers its own hardware instead of trusting a fixed, hardcoded I/O port, and (as of milestones 30-34) a real driver for the NIC that discovery finds, moving real packets through real TX/RX descriptor rings, with a real ARP resolver, IPv4 layer, and UDP layer on top.

CommandWhat it does
pciwalks the legacy CONFIG_ADDRESS/CONFIG_DATA mechanism across bus 0's 32 device slots and prints every real device found — vendor/device ID, class/subclass — independently checkable against QEMU's own default machine model (see Hardware discovery: PCI)
nicenables the e1000 NIC over PCI, maps its MMIO register file, and prints its real MAC address and link-up status — read straight from hardware, not fabricated (see The e1000 NIC driver)
arpexercises the real ARP resolver (arp_resolve()) in four checks: resolves QEMU's default gateway (real external round trip), resolves it again (instant cache hit — zero elapsed ticks), resolves a second real address (QEMU's DNS proxy), and resolves an unreachable address (correctly fails after a real timeout) (see A real ARP resolver)
pingsends a real ICMP echo request to QEMU's default gateway (resolving its MAC via the real ARP resolver first) and verifies a genuine, correctly-matching reply — real IPv4 header, real checksum, real external round trip (see A real IP layer)
dnssends a real, hand-crafted DNS query over real UDP to QEMU's built-in resolver proxy and verifies a genuine, correctly-matching response — real pseudo-header checksum, real answer from a real upstream resolver (see A real UDP layer)

Raw disk I/O

A legacy ATA PIO driver talking directly to the classic ISA IDE ports — polling, not interrupt-driven, with a bounded wait so a missing drive fails cleanly instead of hanging.

CommandWhat it does
diskreads sector (LBA) 1 and prints its content — a fixed signature the test disk image was built with, proving real reads against known content
diskwritewrites a distinct 512-byte pattern to a different sector, reads it straight back, and reports whether all 512 bytes matched

MiniFS (the filesystem)

A minimal custom filesystem: a fixed-layout superblock, a one-sector 16-entry flat directory, and a contiguous per-file data region.

CommandWhat it does
mkfsformats the disk — writes a fresh superblock and an empty directory (destructive: existing files become unreachable)
mkfilecreates a new file with an auto-generated name/content (file0.mfs, file1.mfs, ...) — fails if that exact name already exists
catprints the content of the most recently created file
lslists every file (name + size) plus the superblock's own file count, for cross-checking

VFS

A basic namespace: /system routes to MiniFS (real disk I/O), /devices routes to a second backend reflecting live kernel state — the identical function call reaches two completely different mechanisms depending only on the path prefix.

CommandWhat it does
vfscat <path>reads and prints a file through the VFS — try vfscat /system/file0.mfs (real disk) or vfscat /devices/ticks (live kernel state, no disk touched)
vfswritewrites a fixed demo file to /system/vfsdemo.mfs through the VFS (not MiniFS directly)

Process loading from disk

CommandWhat it does
installwrites the kernel's own compiled-in ring3 test program out to /system/testprog.bin — simulating a program actually being installed on disk
spawnreads that file back through the VFS and launches a brand-new, independent process from it — the shell's own path to "launch a program," in kernel mode; see ring3go above for a ring3 process launching itself a second instance
