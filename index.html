A kernel, written in MiniC

MiniC OS

A multiboot1 x86-64 kernel written almost entirely in MiniC — a small, hand-written systems language with its own compiler, no LLVM. The only hand-written assembly is what's genuinely below what a MiniC function body can express: the 32-to-64-bit boot transition, interrupt entry stubs, and context switching.

a real shell session
> alloc
allocated 64 bytes at 0x5000c040
> map
mapped 0x40000000 -> 0x422000, wrote/read 0xcafebabe
> mkfs
filesystem formatted
> mkfile
created file0.mfs
> spawn
spawned process 0x1
> ps
processes: 0x2 proc0 task=0x7 cr3=0x426000 proc1 task=0x9 cr3=0x444000

Every one of those commands is backed by a real subsystem, not a stub: a free-list heap over a physical frame allocator, real dynamic PML4/PDPT/PD/PT paging, a preemptive scheduler, a custom on-disk filesystem, and a real process loader — all written in ordinary MiniC, all verified in QEMU with a concrete, checkable assertion for every claim (an exact byte count, a register readback, a physical address that genuinely differs between two isolated processes), never just "it didn't crash."

Where this fits

MiniC OS is the kernel-phase destination of the MiniC compiler project — the point where the language stops being exercised by small demo programs and starts being exercised by a real kernel with real constraints (no libc, no register allocator, no forward declarations). Every real language gap MiniC OS surfaced (char literals, char arithmetic, break/continue, 2D arrays, const, and eventually real obj.method() syntax) got fixed as a real compiler feature, not worked around and forgotten.

What's already real

Ring 0 → ring 3, for real

A GDT ring3 code/data pair, a TSS with a per-task RSP0, and an int 0x80 syscall gate — verified by reading back cs=0x1B from inside ring3, not just "a syscall succeeded."

Real process isolation

Each process gets its own PML4, cloned on spawn — two processes mapping the identical virtual address resolve to two genuinely different physical frames, confirmed with a page-table walk, not just "two different numbers came back." A cloned address space's copy of the shared kernel region is stripped of ring3 access too — a deliberate forbidden write from ring3 takes a real page fault, not a silent success.

An NT-style object/handle model

Ring 3 code only ever sees a small integer handle, bounds- and existence-checked on every use — never a raw kernel pointer. Real per-handle rights, too: a handle granted with receive-only access genuinely cannot be used to send, checked at the syscall boundary before the underlying object is ever touched. Extends across processes too — one process can open a handle to another with a requested rights set, and gets back only the intersection of what it asked for and what's actually grantable.

Real IPC

Blocking channel receive reuses the exact same scheduler blocking primitive sleep() already proved, generalized to a second wake condition — no second mechanism invented.

A real filesystem, from scratch

A legacy ATA PIO driver, a custom filesystem ("MiniFS") with a real superblock/directory/data layout, and a VFS routing /system and /devices paths to different backends through the identical function call.

Compiled MiniC running in ring 3

Ring 3 processes are real, minicc-compiled MiniC programs — not hand-assembled blobs — using real obj.method() syntax against a native File/ Channel/Process API, plus a thin POSIX-shaped open/read/write/ close shim layered on top.

qemu-system-x86_64 -kernel minic-kernel.elf
